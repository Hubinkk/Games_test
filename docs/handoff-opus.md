## 2. 环境和每天要用的做法

- 仓库在 WSL 里：`~/Games_test`（Windows 下是 `\\wsl.localhost\Ubuntu\home\liu\Games_test`）。分支 `claude/jolly-clarke-acru9q`。
- **两个 Python 环境，不要混：**
  - 训练：`sim/rl/.venv`（Python 3.12，jax 0.7.2 带显卡、mujoco-mjx 4.0、brax 0.14.2）。jax 再新就和 brax 不兼容。
  - 检验和一切完整身体的事：`~/venv-sys`（mujoco **3.17**）。手写的起身只在 3.17 上成功；检验一律用它。
- **推送**：WSL 里没有凭据，`git push` 会卡住。做法是在 Windows 这边留一份中转的克隆，`git fetch //wsl.localhost/Ubuntu/home/liu/Games_test claude/jolly-clarke-acru9q`，先 `git fetch origin` 并把 origin 的新提交合并进来（云端会话也在往这个分支推），再 `git push origin HEAD:refs/heads/claude/jolly-clarke-acru9q`，最后在 WSL 里 `git pull --ff-only origin …` 跟上。中转克隆里报的 commit-graph、repack 错误可以不管。
- **提交署名**：WSL 里没设身份，用 `git -c user.name=Claude -c user.email=noreply@anthropic.com commit`。只 `git add` 自己改的文件，不要 `git add -A`（目录里有很多不提交的副本和诊断输出）。
- **从 Windows 调 WSL 的命令**：`wsl -d Ubuntu -- bash -lc "..."` 里只要有 `$变量`、`$(...)`、嵌套引号就会坏。稍复杂的都先写成脚本文件再 `bash 脚本`。
- **长训练**用后台方式跑，输出直接重定向到文件（不要接 `grep | tee`，会憋着不出字）。WSL 没有活动的命令时虚拟机可能自己关掉，后台训练会跟着没：训练那条 `wsl` 命令本身要一直挂着。
- **不要用 `pkill -f`**（会把自己的 shell 也杀掉，也可能误杀别人的训练）。用 `pgrep` 找到进程号再 `kill`。别的会话开的进程，让它自己停。
- **显卡只有一块**。两个 JAX 进程同时跑会互相拖慢或者抢显存。一次只跑一个训练；小的试跑加 `XLA_PYTHON_CLIENT_PREALLOCATE=false`。
- 额度有限时的分工经验：需要把很多线索连起来判断的事（设计环境和奖励、查两个身体为什么对不上）自己做；说得清"做什么、做到什么算完"的事（检验、做页面、按清单排查）可以交给另开的会话，但它报回来的结论要自己抽查一次再写进文档。

## 3. 这条线上学到的（比 `docs/next-local.md` 里那 6 条多出来的）

1. **训练和检验共用的数字只能有一份。**走路第一次训练白跑，就是站姿在训练环境和检验脚本里各写了一份，只改了一边。现在都在 `sim/rl/walk_common.py`。新加的环境照这个做。
2. **先看"不加策略时能不能站住"。**原来的站姿重心在脚踝后面，不加控制 1 秒就往后倒。站姿从脚踝前倾 0.07 弧度后才站得住。换站姿、换身体以后先做这个检查（把目标角固定成站姿跑 5 秒），两个身体都做。
3. **训练环境里的成绩会骗人，但方向不骗人。**训练曲线只用来看"在不在学"；选哪一份、过没过关，只看完整身体上的检验。每次评估都存一份副本，挑的时候至少看后面三份。
4. **"接着练"会先把本事练丢。**只恢复策略、不恢复打分网络（价值网络）时，头 1000 万步策略会被练坏（走路第 2 轮：撑的时间 14.9 秒 → 5.1 秒），之后等于从头学。`train_walk.py` 现在每次评估另存一份完整存档 `walk_full_<tag>.npz`（策略 + 打分网络），`--init=` 给它时连打分网络一起恢复。**这段代码写完后只做过小规模试跑，没有在长训练里验证过**；第一次用时先看第 0 步和第 1000 万步的成绩有没有掉。`train_getup.py` 的 `--init` 还是老做法（起身的"接着练"曲线一直是平的，可能也有这个原因）。
5. **镜像是白来的。**身体左右对称，起身的"头转右"就是"头转左"的整体镜像（`sim/rl/mirror_lr.py`），不用再练。以后凡是分左右的动作（侧身起、单侧迈步）先想能不能镜像。
6. **策略外面套一层简单控制，常常比重新训练划算。**朝向控制就是三行（`eval_walk.py --hold`）。但不是都灵：站着被推时"临时改成原地踏步"的反射（`--reflex`）试过，8 N 还是 18/24，没用，要靠训练。
7. **起身那边没查清的事**（都写在 `wiki/灵活度.md` "把头偏向一边练进起身"一节末尾）：
   - 起身的训练现在只有约 400 步/秒，第四、五轮同样的代码有约 6000。elliptic 摩擦锥在起身的训练身体上比 pyramidal 慢 12 倍（接触的几何体多），这解释了一部分；剩下约 13 倍原因不明。走路的训练身体只留了脚的碰撞，约 1.9 万步/秒，不受影响。**再练起身之前先解决这个**，否则一轮要十几个小时。一个没试过的办法：起身的训练身体也只留"会碰地的那几块"（手掌、膝盖、脚、头、胸、骨盆），其余关掉碰撞。
   - 训练里"脸着地"的判据和检验用的不是同一个，训练里的扣分压不下检验的数。再练之前改成同一个。
   - 头的摩擦 0.85 以上时，新的起身方式脸着地约三成（原来"代码强行转头"是 4%）。整体模型里头的摩擦现在还是 1.0，所以**数字花然那边用新策略是退步**。要么整体模型的头改成 ≤ 0.7（和育苗人"头用光滑材料"的决定一致，但实物材料没测），要么数字花然暂时继续强行转头。这要育苗人和云端会话定，不要自己改 `full_build.py`。

## 5. 接下来做什么（按我建议的顺序），和怎么算做成

方向见 `docs/next-local.md`：能落地、稳定的 VR、尽可能强的运动能力。育苗人在试用 Quest 3s，他在意的是：头戴设备续航短、边充边用时脸上发热。所以 VR 这条线上，"花然自己能把腿的事管好、人只用管头和手"是重点，不要设计成需要人长时间戴着头显盯着。

**A. 把走路接进数字花然的一天（小，先做）**
- `sim/day.py` 里现在用手写的静步行（`walk.walk`，1.1 cm/s）。加一个选项（比如 `--walk=rl`，默认先不变），用 `walk_policy.npz` + 朝向控制走同样的距离。照 `--getup=rl` 的做法（`sim/getup_rl.py`、`sim/day_getup_compare.py`）。
- 要看的：走完没摔；用时；**腿上各电机的温度**（走路是持续出力，热模型以前没在这种步态下跑过）；走完以后后面的事（坐、睡）照常。
- 算做成：第 5 天两种走法都跑通，对比表写进 wiki。默认换不换、已发布的页面数据动不动，是云端会话和育苗人的事，不要动 `digital-huaran/` 和 `digital_huaran_day.js`。

**B. "去那里"：朝着一个目标点走（小）**
- 在朝向控制上再加一层：给一个地面上的目标点，转向指令看方位差，前进指令看距离（远了 20 cm/s，近了减速，到 3 cm 内停）。不用训练。
- 算做成（完整身体，每格 8 次，地面 0.6/1.0/1.5）：目标在 1 m 外的 8 个方向（含正后方），都能走到 5 cm 以内并停住，不摔；途中被推 5 N 一次仍能到。把"去那里"加进 `Walk.html` 的巡演（让 `sim/walk_replay.py` 多录一段）。
- 这就是 VR 里用手一指、它自己走过去的那个动作。

**C. 上身跟着人动的时候照样走（中，VR 的核心）**
- 第 2 轮已经在练"上身被摆到随机姿势"（见第 4 节）。接下来要补的：上身不是每 2 秒跳一次，而是**连续地动**（VR 里头和手是连续跟随的）。在训练环境里把上身目标改成平滑的随机轨迹（比如几个正弦叠加，幅度在 `walk_common.UPPER` 的范围内，频率 0.2–1.5 Hz）。
- 再往后：把"上身现在的目标角"放进观测（策略提前知道手要往哪去，可以预先调重心）。这会改观测的长度，旧策略不能直接接着练，要从头练一轮（约 2 小时）。先看不放进观测时够不够好，不够再做。
- 算做成（完整身体，`eval_walk.py --upper --hold`，每格 8 次）：基本项目全不摔；指令 15 cm/s 时实际在 14–16；停下后最后 2 秒挪 < 1 cm。再加一项：单手前伸到最远（肩 −1.5、肘 0）保持 5 秒时站着不倒、走着不摔。

**D. 站着被推时迈步接住自己（中）**
- 现状：站着被推 8 N 是 18/24。走着被推 8 N 是 8/8，说明它会用迈步来接，只是站着时不抬脚。
- 做法建议：不要另练一个策略。在走路的训练里，指令为零时也允许抬脚——把"指令为零时两脚都不抬"的奖励改成"躯干稳的时候不抬，躯干被推歪（倾斜或角速度超过阈值）时按节拍抬脚也不扣分"。第 2 轮推力上限已经加到 12 N，先检验第 2 轮的结果有没有自己学会，再决定改不改奖励。
- 算做成：站着被推 8 N 全过（每格 8 次，三种地面），12 N 过一半以上；同时"站着不被推"时 10 秒里挪动 < 1 cm（不能为了扛推变成一直在踏步）。

**E. 仰面摔倒后起身（大）**
- 建议的路：**先翻身成趴着，再用已有的起身**，不要单独练一个"从仰面直接站起来"。翻身是短动作（2–3 秒），而趴着起身已经很稳。
- 先用手写动作试能不能翻过去（`sim/getup_hands.py` 那种关键帧写法）：一侧手臂上举过头，对侧腿屈膝蹬地加转腰，头转向翻的那一侧。头大（320 g）、手臂短，可能要靠腿和腰。能翻过去哪怕不稳，就拿它当参考动作，照起身的做法练（`getup_env.py` 的结构：跟身体状态的奖励、从动作中间开始、离参考太远就结束）。翻不过去就不给参考动作，奖励只看"躯干的朝向从仰面转到趴着"，让它自己找。
- 训练身体要先对：翻身时碰地的是背包、后脑、手臂、屁股。按"只留会碰地的几块"建一个翻身用的训练身体，先用 `diag_getup.py` 那样的办法对一遍两个身体。注意背上有背包（`backpack` 那块），仰面时是垫着背包躺的，不是平躺。
- 算做成（完整身体，每格 8 次，地面 0.6–1.5，起始姿势是"仰面、四肢随机摆"）：翻成趴着（躯干朝下 ±20°、基本静止）≥ 90%；接上起身后整体站起来 ≥ 85%；左右两侧翻都测（镜像）。头着地时的冲击如实报告。

**F. 保护性摔倒（大，和实物安全直接相关）**
- 目标不是不摔，是摔的时候不伤自己：头不先着地，着地的冲击小。
- 做法建议：在走路的环境里，被推到超过恢复能力（比如 20–30 N）时不立刻结束这一局，而是继续 1.5 秒，奖励看：头的最大着地冲击（越小越好，头先着地重罚）、躯干着地时的速度、手先着地有奖励、关节有没有顶到极限。训练身体要打开头、手、前臂、膝盖、骨盆、胸的碰撞。
- 先量基线：现在的策略被推倒时，头着地的冲击力多大、哪个部位先着地（完整身体，往前、往后、往侧面各 8 次）。没有基线就没法说练了有没有用。
- 算做成：头先着地的比例和头的峰值冲击比基线明显下降（数字如实写），而且不影响正常走路的各项。

**G. 坐下和从座位站起（中）**
- 续航决定它常坐着（充电座）。需要先定座位的高度和形状（`docs/blueprint.md` 里说充电座还没设计），**这一项先问育苗人座位长什么样**，不要自己定。

## 6. 不要做的（沿用，加两条）

- 不要改 `sim/full_build.py` 里身体的结构、重量和头的摩擦。要改先停下来问。
- 不要动 `digital-huaran/`、`digital_huaran_day.js` 和已发布的网页数据。新做的页面可以提交，发布由育苗人或云端会话决定。
- 不要重新设计起身的参考动作（除了已经加的转头）。
- 沿用扭矩上限和 10 rad/s 的转速上限。走路里是"目标角每 2 ms 最多变 0.02 弧度"，新环境照做。
- 结果如实写：没学会就写没学会；数字注明是仿真、每格几次；试过没用的也记下来（比如"从第 0 步就转头""原地踏步反射"）。
- 和育苗人说话用中文，先说结论，再给数字；把技术结果翻译回"像不像、灵不灵活、它在不在乎"。
