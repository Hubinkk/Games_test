## 3. 两种协作办法

**办法 A：保持分工，靠分支传话（不需要新权限，现在就能做）**

- 云端：跑 `day.py`，管 `digital-huaran/`、网页数据。早上（或睡眠阶段）读 `practice-results/` 里最新的 `.json`：`status` 是"练成了"就勾掉队列、更新技能卡片（`走路.md` 的 v2 现在还写着"待训练"）、在给育苗人的报告里写一句；有 `caveat` 的要一起写进去，不要只写"练成了"。
- 本地：每次云端推了新的队列，跑 `night_practice.py`；没过关的开训练、验收、再写结果。训练只在本地做（一块显卡，一次一个）。
- 约定：云端只写 `digital-huaran/`、`digital_huaran_day.js`；本地只写 `sim/rl/`、`practice-results/`；`wiki/` 和 `docs/` 两边都写，推之前先拉。

**办法 B：她的一天搬到本地跑**

- `day.py` 只用 CPU，本地能跑。白天 → 睡眠 → 夜里练习 → 早上报告，在一台机器上连成一圈，夜里真的能重练。
- 云端转为：看报告、整理记忆和 wiki、做网页、和育苗人讨论设计。
- 代价：改掉"`digital-huaran/` 归云端"的约定，要育苗人同意；两边同时写 `digital-huaran/` 会冲突，所以要明确只有一边写。

本地的看法：先用 A 接通（今天就能通），等夜里自动重练做出来、确实需要一晚上跑完一圈时再考虑 B。
