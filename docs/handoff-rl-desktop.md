# 交接：在台式机（RTX 5070 Ti，32 GB 内存）上训练起身

写给在那台电脑上新开的 Claude Code 对话。育苗人 2026-11-10 决定：直接在台式机上做，求快。
先读仓库根目录的 `CLAUDE.md`（规则、用中文和育苗人沟通），再读这一页。分支：`claude/jolly-clarke-acru9q`。

## 现在到哪了

- 花然（55 cm 人偶机器人）在 MuJoCo 仿真里**第一次从趴着站起来了**：手撑起身体 → 两只手轮流往脚这边挪 → 重心到脚上再松手 → 靠腿站起。
  代码 `sim/getup_hands.py`（`hand_walk`），参数 `sim/getup_hands_walk_best.json`。
- 但它**不稳**：地面摩擦 0.6–1.0 成功，1.2 和 1.5 失败；动作参数偏 6% 时只有 2/8 成功。而且松手以后要靠一个手写的平衡控制才站得住。
- 所以要用强化学习把它练稳：照着这条动作练，学会根据身体的感觉随时修正。

## 已经准备好的（`sim/rl/`）

| 文件 | 是什么 | 验证到什么程度 |
|---|---|---|
| `build_rl_model.py` → `huaran_rl.xml` | 训练用的简化身体：去掉手指（换成手掌）、膝换成普通电机；重量、关节范围、扭矩上限不变。3.34 kg，26 个电机 | MJX 能装载和步进 |
| `make_ref.py` → `ref_getup.json` | 参考动作：每 20 ms 一组 26 个电机的目标角，共 17.9 秒 | 在简化身体上直接回放站不起来（预料之内） |
| `getup_env.py` | MJX 环境：目标 = 参考 + 0.3 rad × 策略输出；随机地面摩擦 0.5–1.5、起始偏差、偶尔被推 | 小规模试跑通过 |
| `train_getup.py` | PPO 训练（brax），产出 `getup_policy.npz` 和 `getup_progress.json` | **只在没有显卡的机器上试跑过**：16 个身体、20 万步、30 分钟，流程走通，没有学会（规模太小，预料之内） |
| `policy_np.py`、`check_export.py` | 用纯 numpy 读策略；核对和训练库算的动作一致 | 一致（最大相差 1.75e-07） |
| `eval_full.py` | 把策略放回完整身体（有手指、绳驱膝）里，在 5 种地面摩擦下检验 | 用没训练的策略跑通 |
| `setup_desktop.sh` | 建虚拟环境、装工具、检查 JAX 看不看得到显卡 | **没有在带显卡的机器上跑过** |

试跑通过的版本组合：`jax==0.7.2`、`mujoco-mjx==4.0.0`、`brax==0.14.2`。
**最新的 jax（0.12）不行**：它删掉了 brax 0.14.2 还在用的 `jax.device_put_replicated`。

## 要做的事，按顺序

1. **找到 Linux 环境。**育苗人说以前装过、一直没用。PowerShell 里 `wsl -l -v`；JAX 的显卡版只支持 Linux，Windows 上要用 WSL2。
2. **在 Linux 里**克隆仓库（已经有就拉最新），`cd sim/rl && bash setup_desktop.sh`。
   - 没验证过的风险：5070 Ti 是 50 系，`jax[cuda12]==0.7.2` 自带的 CUDA 库不一定认得它。脚本第 4 步会查。认不出来就换能认的 jax 版本，但要同时保证和 brax 兼容（必要时升级 brax，或给 brax 打补丁），换完重跑 `python train_getup.py --smoke` 和 `python check_export.py`。
3. **训练**：`python train_getup.py --steps=100000000 --envs=4096`。每次评估会打印"松手后站着的时间比例"。
   - 这是第一次真的训练，奖励和超参数都没调过，很可能要改。先看 1000 万步内"平均骨盆高"和"站着的时间比例"有没有上升。
   - 奖励在 `getup_env.py` 的 `step` 里：跟踪参考 0.5、站直和高度（松手前只算两成）、松手后站住每步 +3、用力和抖动的小惩罚。
4. **检验**（用系统的 Python 和 mujoco，不需要显卡）：`python eval_full.py getup_policy.npz`。
   - 目标：5 种摩擦里比"只照参考做"多站起来；理想是 5/5。
   - "只照参考做"在这个脚本里是 0/5，这是对的：原来成功的那次在松手后接了手写的平衡控制，这里故意不接。
5. **如果简化身体上学会了、完整身体上不行**：差别主要在手。简化的手掌没有手指那一段（完整模型里撑起时身体回到前倾 69°，简化身体只到 83°）。可以给手掌长度、位置加随机，或者给简化身体加一段软的手指。
6. **学会以后**：把策略接进 `sim/day.py`（现在用 `--getup=hands`），让数字花然用学到的动作起身；更新 `wiki/灵活度.md`、`wiki/待解决的问题.md`、`docs/handoff.md`；提交推送。

## 要守住的约定

- 沿用整体模型的扭矩上限和 10 rad/s 的转速上限（环境里是每 20 ms 目标角最多变 0.2 rad）。
- 对育苗人如实汇报：没站起来就说没站起来，数字注明是仿真还是估算。
- 还没解决的相关问题：腰、脖子、肩、肘在起身时顶到力气上限；仰面摔倒时怎么起身还没做；热参数是估算的（发热测试 `docs/heat-test-v1.md` 还没做）。
