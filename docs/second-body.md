# 第二个身体：用现有技术做一个像人一样行动的仿生机器人

目标：做一个能像人一样行动的仿生机器人，未来可以用于：
1. **VR 里的第二个身体**：人戴上头显，"住进"机器人的身体
2. **模拟玩家本人的缺陷与改良**：把玩家的身体做成模型，看它哪里受限、怎么改善
3. **模拟机器人自身的缺陷与改良**：受损、补偿、换部件、重新学

## 核心：一套身体描述，三个世界共用

```
        玩家的身体  ──动作捕捉──▶  玩家的数字孪生（仿真）
            ▲                              │ 同一套骨架、关节和限位描述
     触感 / 身体地图                       ▼
            │                        机器人的数字孪生（Isaac Sim）
        真实机器人  ◀──遥操作／策略──      │
            └────────── 身体地图：两边的状态都用同一种"感受语言"显示
```

人和机器人用**同一种格式**描述身体（骨架、关节、活动范围、力量、状态）。这样：
- 玩家的动作可以直接映射到机器人身上
- 玩家身体的限制（比如一侧膝盖活动受限）可以"装"到机器人或仿真里
- 机器人的状态可以翻译成玩家能感受到的东西

这就是「一つの身体二つの世界」最直接的落地方式。

## 三种用法，以及现有技术能做到哪一步

### 1. 第二个身体（具身遥操作）

| 环节 | 现有技术 | 能做到 | 做不到 / 难点 |
|---|---|---|---|
| 看 | 机器人头部双目摄像头 → VR 头显 | 第一人称立体视觉 | 网络延迟大于约 100 ms 时容易晕 |
| 动 | 头显的头部、手部和身体追踪 → 动作重定向 | 上半身基本可以一比一跟随 | 下半身不能直接照搬：平衡要交给机器人自己的"脊髓层"，玩家只给"往哪走、蹲下、转身"这样的意图 |
| 感 | 振动马达背心、手套 | 碰撞、心跳、发热等提示 | 真实的力反馈和触觉传递仍然很难 |
| 身体状态 | 身体地图 | 玩家能"感到"机器人累了、哪里吃力 | — |

已有先例：斯坦福的 HumanPlus 让人形机器人实时模仿人的全身动作；OpenTeleVision 用 VR 头显做沉浸式遥操作。宇树等厂商也已经支持用头显操控人形机器人。

**关键设计**：玩家负责"想做什么"，机器人负责"怎么不摔倒"。这正好是之前的分层：大脑 / 脊髓 / 关节神经节。

### 2. 模拟玩家本人的缺陷与改良

| 环节 | 现有技术 |
|---|---|
| 采集玩家身体 | VR 追踪、手机摄像头姿态估计，测量身高、肢体长度、各关节活动范围、左右差异 |
| 建立模型 | 肌骨仿真（如 OpenSim、基于 MuJoCo 的 MyoSuite），或者简化成和机器人相同的骨架模型 |
| 找出受限的地方 | 比较左右两侧、比较不同动作，标出活动范围小、发力不均的部位 |
| 尝试改良 | 在仿真里试：多练某个动作、加辅助装置、调整姿势，看整体会怎么变 |
| 让玩家"从外面看自己" | 把玩家的限制装到机器人或虚拟身体上，玩家在 VR 里看着另一个身体用自己的方式走路 |

最后一项是这个作品独有的体验：**人第一次从外面看到自己身体的习惯和补偿。** 比如一侧膝盖不舒服时，另一侧在悄悄多扛，就和身体地图里四足机器人的情况一样。

注意：这是体验和自我观察工具，不能当作医疗诊断。涉及身体数据时，要保护隐私。

### 3. 模拟机器人的缺陷与改良

这一部分已经在仓库里做了原型：
- `BodyMap.html`：缺陷如何传播、补偿的代价
- `FigureAnatomy.html`：每个部件能否实现，以及原因
- `docs/knee-joint-v1.md`：第一个可以实际测试的改良部件

做法：先在 Isaac Sim 里改（换部件、调减速比、模拟受损），确认有效之后再动手做实物。

## 现有技术的整体边界

| 已经能做 | 仍然很难 |
|---|---|
| 全尺寸人形机器人的行走、跑、跌倒爬起（宇树 G1 / H1 等） | 像人一样柔顺安静的动作（驱动问题） |
| VR 遥操作上半身和双手 | 低延迟、不晕的全身遥操作，尤其是行走 |
| 仿真里训练行走和受损后的补偿 | 人手级灵巧和触觉 |
| 振动类触感反馈 | 真实的力反馈 |
| 人体动作捕捉和简化的肌骨模型 | 续航（几十分钟到两小时） |

## 分阶段路线（从不需要硬件开始）

| 阶段 | 内容 | 需要的东西 |
|---|---|---|
| A. 纯数字的第二个身体 | 戴 Quest 在 UE5 / Isaac 里操控一个虚拟机器人身体，接入身体地图；录下玩家自己的动作，生成玩家的数字孪生，并给它加上缺陷 | 台式机（RTX 5070 Ti）、VR 头显 |
| B. 一条真实的手臂 | 用 SO-101 机械臂做第一段"第二个身体"：玩家的手臂动，它跟着动，状态显示在身体地图上（SO-101 当初因为没有身体被放下，但在这里正好可以当第一条手臂） | SO-101、LeRobot |
| C. 小型全身 | 55 cm 人偶作为缩小版的第二个身体。人在 VR 里能适应不同大小的身体，可以按比例映射 | 自制人偶，从膝关节 v1 开始 |
| D. 全尺寸 | 在商用人形机器人外面加角色外壳，或者在 C 的基础上放大 | 预算明显增加 |

**建议先做 A。** 它不需要任何新硬件，而且就是最初构想里的 VR 作品本身：玩家在 VR 里学会一个陌生的身体，看见它的内部，看见自己的影子。
