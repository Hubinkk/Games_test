# 人偶机器人 · MuJoCo 物理验证

这是 `FigureAnatomy.html` 那台 55 cm 人偶的第一个**物理模型**。目的只有一个：在动手做实物之前，先在物理上验证这个身体站不站得稳、关节的力气够不够。

笔记本（RTX 5060）就能跑，MuJoCo 主要用 CPU 计算，不需要 Isaac Sim。

## 运行

```bash
pip install mujoco
```

```bash
python figure_test.py
```

```bash
python figure_stress.py
```

```bash
python walk.py --view
```

想看 3D 画面（会打开一个窗口，测试结束后人偶会一直重复深蹲）：

```bash
python figure_test.py --view
```

只想拖动关节、随便看看模型：

```bash
python -m mujoco.viewer --mjcf=figure55.xml
```

在这个窗口右侧的 Control 面板里，可以拖动每个关节的滑块。

## 文件

| 文件 | 内容 |
|---|---|
| `figure55.xml` | 模型：24 个关节、约 2.95 kg、每个关节的活动范围和扭矩上限；脚宽 4.4 cm |
| `figure_test.py` | 三项测试：站立、深蹲、推一下，并对照膝关节 v1 的设计目标 |
| `figure_stress.py` | 压力测试：快速站起、有无平衡控制器的抗推、单腿站立 |
| `mjcf_to_urdf.py` | 把模型转换成 URDF（`figure55.urdf`），供 Isaac Sim / Isaac Lab 使用 |
| `isaac/figure55_cfg.py` | Isaac Lab 机器人配置草稿，详见 `docs/desktop-isaac.md` |
| `tendon_knee.py` | 绳驱膝关节：测肌腱线要承受的拉力 |
| `walk.py` | 静步行测试：手写步态 + 平衡控制器 |
| `balance.py` | 手写的重心反馈平衡控制器（"脊髓层"的最简版） |

## 模型里的估算值

| 部位 | 质量 | 说明 |
|---|---|---|
| 骨盆 | 0.75 kg | 含电池约 0.4 kg，重心低 |
| 腹部＋胸腔 | 0.70 kg | 含大脑、风扇、肩部驱动器 |
| 头＋颈 | 0.28 kg | 二次元的头偏大，所以要尽量轻 |
| 每条腿 | 0.44 kg | 膝电机放在大腿根部（近端布置） |
| 每条手臂 | 0.17 kg | |

关节扭矩上限：髋俯仰和膝 2.8 N·m（来自 `docs/knee-joint-v1.md`），髋侧摆 2.0，踝 1.5，肩 1.0，肘 0.6，颈 0.3。

这些都是**设计目标和估算**。做出实物、称完重量以后，直接改 `figure55.xml` 里的 `mass` 和 `forcerange`，再跑一次测试，就能知道改动带来的影响。

## 第一次运行结果（MuJoCo 3.17，2026-11-05）

| 测试 | 结果 |
|---|---|
| 站立 3 秒 | 站稳；骨盆高 28.2 cm，躯干倾斜 1.1°；膝关节只需约 0.24 N·m |
| 深蹲（膝弯到 1.6 rad，最低点停 2 秒） | 完成，没有摔倒；最低点每侧膝关节约 **1.10 N·m**，峰值 1.13 N·m（占上限 40%） |
| 胸口水平推 0.1 秒 | 1 N、2 N 站住；4 N 摔倒（还没有平衡控制器，属正常） |

**结论**：双腿深蹲需要约 1.1 N·m，和 `docs/knee-joint-v1.md` 手算的 1.2 N·m 基本一致；膝关节 v1 估算的持续 1.35 N·m 够用。单腿支撑、起身和跌倒后爬起还没测，3 N·m 的峰值目标仍需台架实测确认。

## 压力测试结果（`figure_stress.py`，2026-11-05）

| 测试 | 结果 |
|---|---|
| 从深蹲（膝 2.0 rad）快速站起 | 1.0 秒：膝峰值 1.48 N·m；0.6 秒：1.77；0.4 秒：**2.29 N·m**（占 2.8 上限的 82%） |
| 推胸口，只有关节 PD | 2 N 站住，4 N 起摔倒 |
| 推胸口，加平衡控制器（`balance.py`） | **4 N 也能站住**，6 N 起摔倒 |
| 单腿站立，小幅抬腿 | 站住 |
| 单腿站立，大幅抬腿 | 摔倒（脚宽 2.8 cm 时）→ 脚宽改为 4.4 cm 后**站住** |

**脚宽对照实验**（大幅抬腿）：

| 脚宽 | 抬腿 0.4 | 抬腿 0.7 | 抬腿 1.0 |
|---|---|---|---|
| 2.8 cm（原设计） | 站住 | 摔倒 | 摔倒 |
| 3.6 cm | 站住 | 摔倒 | 摔倒 |
| **4.4 cm（现在模型采用）** | 站住 | **站住** | **站住** |

**结论**：
1. 膝关节 2.8 N·m 的上限够用：最激烈的 0.4 秒快速站起也只用到 82%。3 N·m 的峰值目标可以保留，作为跌倒后爬起这类动作的余量
2. 单腿平衡的瓶颈是**脚太窄**，不是力气不够。脚宽要做到约 4.4 cm（约为身高的 8%），可以用靴子造型掩盖，这正是之前"脚比角色设定稍大"的做法
3. 平衡控制器是手写的重心反馈，能把抗推能力从 2 N 提高到 4 N。用强化学习训练的策略应该能做得更好

## 静步行测试（`walk.py`，2026-11-05）

手写步态加平衡控制器：每一步先把重心完全移到支撑脚上方，再迈另一条腿。

| 步长 | 每步用时 | 结果 | 关节峰值（N·m） |
|---|---|---|---|
| **3 cm** | **2.4 秒** | **走完 6 步，前进 12.3 cm，横向偏移 1.2 cm** | 髋俯仰 1.40、膝 0.77、踝 0.78、髋侧摆 1.32 |
| 3 cm | 1.6 / 1.2 秒 | 摔倒 | 失败时髋侧摆顶到 2.0 上限 |
| 5 cm | 2.4 / 1.6 / 1.2 秒 | 摔倒 | 髋俯仰接近 2.8 |
| 7 cm | 2.4 / 1.6 / 1.2 秒 | 摔倒 | 髋俯仰、膝都顶到 2.8 |

**结论**：
1. 这个身体**能走**，但手写的静步行只能做到约 1 cm/s，非常慢
2. 想走快、步子迈大，需要"动步行"：重心不必每时每刻都在脚上方，而是像人一样边倒边接住。这要在 Isaac Lab 里用强化学习训练（见 `docs/desktop-isaac.md`）
3. 失败时髋侧摆常常顶到 2.0 N·m 的上限。这可能是摔倒的结果而不是原因，但训练动步行时要留意：如果学出来的策略也经常用满髋侧摆，就把这个关节的上限提高到和髋俯仰一样（2.8 N·m）

## 绳驱膝关节测试（`tendon_knee.py`，2026-11-05）

把膝关节改成"绳轮＋肌腱线"驱动：大腿骨里的电机带动绳轮，同一个绳轮上反向绕两根线，前线相当于股四头肌，后线相当于腘绳肌。线绕过膝部半径 1 cm 的滑轮（相当于髌骨），每根线预紧 10 N。运行后会生成 `figure55_tendon.xml`。

| 动作 | 结果 | 前线（股四头肌）最大拉力 | 后线（腘绳肌） |
|---|---|---|---|
| 站立 | 站稳 | 44 N | 10 N（预紧） |
| 深蹲到 1.6 rad | 完成 | 144 N | 10 N |
| 0.4 秒快速站起 | 完成 | **250 N（约 26 kgf）** | — |
| 静步行 6 步 | 走完，前进 12.5 cm | 90 N | 50 N |

**换算成零件要求**：
- 线的断裂拉力至少 **750 N（约 77 kgf）**（安全系数 3）
- 绳轮半径 3 mm 时，绳轮需要 **0.75 N·m**；半径 5 mm 时需要 1.25 N·m
- 和手算的 230 N 基本一致；力臂在整个动作中保持 10 mm（滑轮的作用）

**结论**：绳驱膝关节在仿真里能完成全部动作。真正吃力的只有前线（股四头肌），后线只在走路时用到约 50 N，所以前后两根线可以选不同粗细。

## 已知的简化

- 踝关节在设计上由跟腱拉杆驱动，这里先简化为直接驱动
- 只有关节层的 PD 控制，**还没有平衡控制器**，所以"推一下"测试推倒了也是正常的。平衡要靠下一步训练的行走策略
- 没有模拟电机发热、减速器回差、线缆和外壳
- 身体各部分之间不做碰撞检测，只和地面碰撞
